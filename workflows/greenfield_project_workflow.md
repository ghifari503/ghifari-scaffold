# Greenfield Project Workflow

Use this workflow only after `start` detects zero target-project folders under `development/`, excluding scaffold-owned defaults such as `README.md` and `_project-template/`, and selects `greenfield_project` mode.

1. G0: Record auto-route result. Do not create source code or install tools.
2. G1: Ask the founder for project name, problem, users, desired outcome, first feature candidate, constraints, and available references. Create the project charter when enough input exists.
3. G2: Create the minimum requirement baseline and task breakdown for one approved first feature.
4. G3: Propose stack, architecture, repository structure, QA approach, and bootstrap plan. Wait for founder approval.
5. G4: Create documentation-only target shared context, open the greenfield pre-coding gate, and record allowed write paths.
6. G5: Search relevant skills, bootstrap only the approved technology and paths, then implement one selected first-feature slice.
7. Continue with the normal feature slicing, QA, shared-context, memory, and handoff rules.

The current project remains a proposal until G3 and G4 are approved. `start` never grants permission to bootstrap a framework or write product code by itself.
